# Security limitations

Known gaps. Docker, MCP and signatures do not make this system secure by themselves; each control below has edges.

1. **The Swift helper is partly verified.** It has been built on macOS, paired with the broker and completed a fake-account login, which exercised Keychain storage, the approval prompt and the loopback server. `Crypto.swift` is also checked byte-for-byte against `src/shared/crypto.ts` by `scripts/verify-crypto-interop.sh`. Denial, purchase approval, Touch ID and nonce replay protection have not been exercised. Automated tests use the TypeScript dev helper. Test those flows by hand before trusting it with real accounts.
2. **No isolation from the same macOS user.** Anything running as you with Docker access can `docker compose exec` into the broker, read its volume and keys, change grants, or read `./secrets/worker_token` and `~/.agentvault/agent-token`. The native prompt plus Touch ID still gates logins and purchases. See [threat-model.md](threat-model.md) for the separate-user mitigation.
3. **Docker Desktop is a Linux VM.** Isolation is the VM plus namespaces and dropped capabilities, not a hardware boundary. Docker Desktop's own processes and anyone with docker socket access are effectively root over the containers.
4. **`host.docker.internal` reachability.** The broker reaches the helper over the host network path; any host process can also connect to port 47800. Requests are signed, so strangers get nothing, but they can cause prompts only if they hold the broker key. On Linux hosts with `ufw`, container-to-host traffic may be blocked.
5. **Chromium sandbox is off.** Playwright disables it by default in containers; the container (non-root `pwuser`, read-only root, no capabilities) is the sandbox. A Chromium exploit lands in the worker, which holds passwords in transit and live cookies.
6. **The worker is in the credential TCB.** It types the password and holds the session. Compromise exposes secrets of any session it handled while running.
7. **Checkout enforcement is proven only for reviewed adapters.** With a `checkout.submitPath`, the boundary is exact. Without one, a regex heuristic blocks checkout-like non-GET/HEAD requests and forces manual checkout. It can miss unusual paths (GET-based purchases, third-party payment origins you allowlist) and can block innocent ones.
8. **Approval binds to the displayed order, not the cart.** The hash covers the summary read from the DOM just before the click. A merchant can display one thing and charge another, and a page that renders a different summary at the submit moment than it did earlier is only caught if the displayed summary differs.
9. **DNS rebinding TOCTOU.** The worker resolves a hostname to reject private addresses; Node's fetch then resolves again. A hostile DNS server can answer differently the second time. Reduced by allowlisting origins, not eliminated.
10. **Redirects are handled by hand.** Playwright does not route redirect hops (found by test), so the worker fetches with `route.fetch({ maxRedirects: 0 })` and vets each `Location` before fulfilling. This costs fidelity (some sites behave differently) and is a custom path to maintain.
11. **WebSocket filtering is origin-level.** `routeWebSocket` applies the same allowlist at connect time; message contents are not inspected.
12. **Scrubbing is pattern or known-value based.** Passwords and cookie values known to the session and 13 to 19 digit card-like sequences are redacted. Other secrets on a page (one-time codes, tokens, address data) are returned as text. Screenshots cannot be scrubbed and are off unless `screenshots: true`.
13. **Prompt-injection detection is advisory.** Six regexes. Real defence is limited capability plus human approval.
14. **Usernames are stored unencrypted** in SQLite (`accounts.username`). Not secrets, but PII. Order totals and merchant names are in `transaction_approvals`.
15. **No rate limiting** on tool calls, login requests or prompts. A looping agent can spam you with prompts. Only a cap of 8 concurrent browser sessions exists.
16. **Locked Mac or no GUI session.** The helper returns `unavailable` (or never answers; the broker times out after about 130s). The broker treats it as denied. Logins on `prompt` grants and all purchases stop working until you are present; `chat` and `auto` grants are the opt-in way around this for logins.
17. **Pairing is trust on first use.** `agentvault pair` pins whatever key the helper prints. Anyone who can run admin commands can re-pair.
18. **Audit log is not tamper-evident.** It lives in the SQLite DB that the broker owner can edit.
19. **Worker-broker traffic is plain HTTP** with a shared token on an internal network. Anything on that network with the token can call the worker.
20. **Chat and auto grants remove the native prompt from logins.** An `auto` grant signs in with no human at all. A `chat` grant is only as strong as your Telegram or Discord account, and that provider sees the agent name, site, account id and request id. Both need the account's `unattended` flag in the helper, so a compromised broker can release those passwords without asking. Purchases still need the native prompt. A Discord channel set up with Hermes' own bot lets the agent delete or edit the prompt; an edited prompt is denied, so this can only make logins time out. See [ADR 0007](adr/0007-configurable-login-approval.md), [ADR 0008](adr/0008-discord-chat-approval.md) and [ADR 0009](adr/0009-discord-shared-bot-channel.md).
21. **Auto approval is unverified on macOS.** The Swift `unattended` path works for `chat` grants, but `auto` grants have not been run. Credentials are stored `WhenUnlockedThisDeviceOnly`, so a release while the screen is locked may fail and return an error.
22. **Real sites are untested.** Only the mock shop has run. Bot detection, 2FA, CAPTCHAs and changing markup are unaddressed; see the pilot guidance in [operations.md](operations.md#phase-6-real-site-pilot).

## Hardening from the adversarial review

An independent review pass found and this branch fixed: purchase-path bypass via case, trailing slashes, `;params` or encoding (paths are now normalised); unbounded order summaries that could pad or spoof the native prompt (now capped and stripped of control/format characters, totals shown first); approvals spendable by page scripts or prefetches (only top-level navigations during an agent action count, and the pre-action summary is cleared afterwards); prompt flooding (one pending prompt per session); racing logins (conditional session upgrade); malformed `Location` headers hanging requests; WebRTC UDP egress (disabled via Chromium flags). Still open: secret scrubbing only matches exact values of 6+ characters, so re-encoded cookies or very short passwords can pass through page text if a trusted site echoes them; the worker session cap is global, not per agent.
